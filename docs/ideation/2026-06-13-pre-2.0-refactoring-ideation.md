# Ideation: High-Value Refactoring Before the 2.0 Release

## Grounding Context

**Codebase context:** Deneb is a Power BI custom visual for declarative Vega/Vega-Lite visualization — an npm-workspaces monorepo (Turbo orchestration, custom Webpack 5 build) with React 19, Zustand, Monaco, Fluent UI, TypeScript 5.6. Version 2.0.0 is about to release (`next` → `main` promotion). Two Zustand stores (root visual + app-core) are joined by a sync layer (`src/lib/state/create-slice-sync.ts`). The `@deneb-viz/powerbi-compat` package is a singleton enforced by convention (peerDependency + tsup `external`, tsc-only build for const-enum inlining). Recent `next` work: rendering-lifecycle coordinator (U8–U11), row-window limit 10k→30k (U6). Bundle ceiling ~2MB (.pbiviz practical limit).

**Past learnings (docs/solutions/):** The most recurrent bug class is multi-writer state (4 documented incidents). The segmented-fetch solution doc explicitly defers an orchestrator-level integration-test harness as "deserves a dedicated PR". Load-bearing build invariants (per-session `.tmp/` wipe, sequential `build:package`, `npx --no turbo`) exist only as prose. The "Mirrors"/"keep in sync" comment grep is documented as a scan that historically yields real fixes.

**External context:** tsup bug #998 (peerDeps can still be bundled — explicit `external` arrays required); const-enum/isolatedModules incompatibility (TS#37774, TS7 watch item #56631); Monaco→CodeMirror 6 is the largest bundle lever but high-risk (Sourcegraph postmortem); industry pre-major hardening = remove announced-deprecated shims, stamp removal versions, freeze public API surface; barrel-file audit is the natural pre-major move (TS#51418).

**Verified during ideation:** the stale "pre-1.10" version markers are already fixed (`CONTEXT_MENU_SPLIT_VERSION` is `'2.0.0'` with an explanatory comment), CI already gates `validate-config-for-commit`, and `config/features.json` contains exactly one flag (`data_drilldown: false`).

## Ranked Ideas

### 1. Build the fake-host integration harness for `update()`/lifecycle orchestration
**Description:** Mocked Zustand slices + a scripted fake `IVisualHost` driving the real `resolveDatasetUpdateAction` orchestrator and the U8–U11 rendering-lifecycle coordinator through named scenarios (segmented fetch, viewer/editor transitions, resize storms, safety-net close paths). Include the `Record<DisplayMode, boolean>` exhaustiveness-guard upgrade flagged in the same doc.
**Warrant:** `direct:` docs/solutions/logic-errors/segmented-fetch-viewer-editor-transition-quirks-2026-05-27.md:314 — "A pragmatic harness — mocked state slices + a fake `#host` — is the right shape but the choice deserves a dedicated PR." Five of six ideation frames independently converged on this.
**Rationale:** The rendering lifecycle was rebuilt across four consecutive PRs in the final pre-release stretch; it is the newest, most async, least integration-tested code shipping in 2.0. The harness converts every future host-quirk fix from manual smoke-testing into a cheap regression test, and is the prerequisite for safely decomposing `src/index.ts` later.
**Downsides:** Test-infra investment during release endgame; harness-shape decision (node-env fake host vs. adopting @testing-library) needs team alignment.
**Confidence:** 90%
**Complexity:** Medium
**Status:** Unexplored

### 2. Stamp the persisted-state epoch at 2.0: versioned `stateManagement` schema + ordered migration registry + fixture replay
**Description:** Add a schema version to the persisted `stateManagement` payload, replace scattered `isNewerVersion` gates in `src/lib/persistence/migration.ts` with an ordered `{fromVersion, migrate}` registry applied in sequence on load, and replay a corpus of captured pre-2.0 persisted payloads through the full migration pipeline in CI. Apply the PR #619 cardinality-audit checklist (grep literal writes, spread-preserve, non-default-key tests) as the test template for every new key.
**Warrant:** `direct:` `migration.ts:242` (`isNewerVersion` gate pattern); `denebMetaVersion` already exists as a stamp (`src/lib/persistence/model/settings-state-management.ts:29`); CLAUDE.md states the property "grows as new per-spec configuration is added"; three separate migrations converge on 2.0 (context-menu split, support-field defaults, signal migration).
**Rationale:** The only genuine one-way door in this list — every report saved after release locks in whatever shape ships. 2.0 is the largest migration event in the project's history, and a failed migration reaches users' saved reports where no redeploy can fix it. Doing this post-2.0 means one more unversioned legacy shape to sniff forever.
**Downsides:** Touches the highest-stakes code right before release; matching-channel smoke tests still required (fixtures reduce but don't eliminate them, per the cross-GUID property-isolation learning).
**Confidence:** 85%
**Complexity:** Medium-High
**Status:** Unexplored

### 3. Ship a 2.0 deprecation ledger
**Description:** One checked-in ledger stamping every shim and `@deprecated` symbol with introduced / warns-since / removed-in: the `pbiContainer`→`denebContainer` signal shim (currently spread across powerbi-compat, vega-runtime, and json-processing), the deprecated signal constants (`packages/vega-runtime/src/lib/signals/deneb-container.ts:44` has `@deprecated` with no removal target), and an explicit ship/park/delete decision on `data_drilldown` — the only flag in `config/features.json`, currently `false`. Optionally evaluate migrate-once-and-persist for the signal shim as a 2.x follow-up.
**Warrant:** `direct:` file citations above; `external:` the standard shim-lifecycle rule — deprecations announced at a major are removed at the next one, which only works if start dates are recorded.
**Rationale:** Breaking-change amnesty expires at release; anything riding into 2.0.0 unstamped is contractually alive until 3.0. The repo's own history (version gates targeting a 1.10 release that never shipped) shows the cost of un-tracked shim lifetime.
**Downsides:** Mostly policy; the flag decision needs roadmap authority; low direct code value.
**Confidence:** 80%
**Complexity:** Low
**Status:** Unexplored

### 4. The "Mirrors X" sweep: mechanize ~20 prose contracts
**Description:** A census found 17–24 live "Mirrors…"/"MUST match…" comments — e.g. `packages/app-core/src/app/editor/components/preview-area.tsx:40` (references issue #480), `src/app/platform-search-contributions.ts:26` (contract spans two packages), `src/lib/dataset/support-field-provider.ts:23` ("Order must match plan.fields"), and the bidirectional data-tab/source-tab dataset-viewer mirror. Each becomes a shared-code extraction, a type-level constraint, or a divergence-failing test; the comment is deleted either way. New mirror-comments become review flags.
**Warrant:** `direct:` enumerated grep hits plus the team's own playbook (docs/solutions/best-practices/extract-shared-semantics-to-avoid-dual-maintenance-2026-04-24.md) stating this scan "historically yields real fixes."
**Rationale:** Each prose contract is a deferred two-writer bug — one already produced tracked issue #480. The list is finite and enumerable today, and the authors' context is freshest now.
**Downsides:** Some extractions cross app-core layer boundaries and need placement decisions; a few mirrors may be cheaper to leave as divergence tests.
**Confidence:** 85%
**Complexity:** Medium
**Status:** Unexplored

### 5. Invariant canary pack: convert documented rules into CI failures
**Description:** Following the in-repo precedent (`packages/app-core/src/__tests__/architecture-boundaries.test.ts`): (a) a workspace test asserting the powerbi-compat singleton contract — peerDependency + tsup `external` pairing in every consumer, plus a dist-scan for accidentally inlined singleton code; (b) build-script invariant checks (`.tmp/` wipe present, sequential `build:package` before webpack, `npx --no turbo`); (c) a static assert that the rendering safety-net bound stays ≤ 10s (`src/index.ts:105`, a certification ceiling); (d) a state-channel ownership registry (channel → owner → direction → post-hydration source of truth) with a single-writer canary.
**Warrant:** `direct:` CLAUDE.md's manual three-step singleton checklist is the only current enforcement; four documented multi-writer incidents; `external:` tsup bug #998 means peerDependencies alone don't protect.
**Rationale:** These invariants break silently and are most likely to break exactly when post-2.0 contributors add packages or "clean up" scripts. Multi-writer state is the repo's most recurrent bug class, and past single-writer audits also uncovered deletable dead state.
**Downsides:** Several small checks rather than one feature; the ownership registry needs cross-owner agreement on who owns each channel.
**Confidence:** 85%
**Complexity:** Low-Medium
**Status:** Unexplored

### 6. 30k-row pipeline benchmark with budget gates
**Description:** Extend the existing data-core `__bench__` seam (plan-builder/row-builder micro-benches) to an end-to-end dataset-mapping benchmark at 1k/10k/30k rows — categorical extraction → `buildProcessingPlan` → per-row `buildDataRow` → `patchSpecWithData` — with asserted budgets, wired to CI or a documented `npm run bench` gate.
**Warrant:** `direct:` `capabilities.json:362` (`"count": 30000`) is the only place the new ceiling exists — nothing proves the pipeline holds a time/allocation budget there; the limit was raised in this release cycle (U6).
**Rationale:** The data ceiling tripled in the same window the rendering lifecycle was rebuilt; any accidental O(rows) regression now costs 3×, and only field reports would catch it. A standing benchmark also makes the next limit debate (50k?) evidence-based instead of intuition-based.
**Downsides:** Benchmark stability in CI is finicky; budgets need calibration to avoid flaky gates.
**Confidence:** 80%
**Complexity:** Low-Medium
**Status:** Unexplored

### 7. Freeze the 2.0 public API surface
**Description:** Replace wildcard barrels (18 `export * from` across 11 package `index.ts` files; 5 in app-core alone) with explicit named exports or per-package export snapshots (api-extractor-style diff tests), and promote `apps/web-client-sample` — which already consumes `@deneb-viz/app-core` as a real external embedder — to a CI-gated contract test of that surface. The powerbi-compat endpoint-import pattern is the in-repo precedent to extend.
**Warrant:** `direct:` grep-verified barrel counts; `packages/powerbi-compat/src/index.ts` already documents "Consumers should import specific endpoints"; the sample depends on `"@deneb-viz/app-core": "*"`. `external:` TS#51418 (barrel-file costs).
**Rationale:** A major version is when an accidental API becomes a permanent one — every internal rename after 2.0 is a potential breaking change to embedders. Explicit surfaces also make the deprecation ledger (#3) enumerable and help tree-shaking against the ~2MB bundle ceiling.
**Downsides:** Deciding what is actually public per package is real API-design work; narrowing exports too close to the cut could surprise the sample app or external embedders.
**Confidence:** 75%
**Complexity:** Medium
**Status:** Unexplored

## Sequencing Note

Ideas 1–3 are genuinely release-coupled (one-way doors or amnesty windows that close at the 2.0 cut). Ideas 4–7 are high-value but can trail the cut without losing much of their worth.
